# P4e 第一次组内远程内测：发现与范围决策

日期：2026-08-07  
性质：六人、同一核心流程的形成性内部可用性内测；不是具有统计代表性的用户研究。

本记录只使用离线汇总后的匿名聚合结果和可复现工程审计，不包含测试者姓名、编号、访问码、URL、学习档案、题目或原始开放反馈。

## A. 已确认 bug

### A* 在 Markdown 中的显示

- **观察事实**：有反馈报告 A* 算法名中的星号在回答显示中可能消失；工程审计确认学生回答使用 Markdown 渲染，而同一文本中多个未转义的 `A*` 可能被 Markdown 解释为强调标记。
- **工程判断**：这是展示层问题，不是课程材料、检索或回答语义错误。
- **本轮动作**：仅在学生可见的 Markdown 展示视图中转义算法名的星号；保留正常粗体、列表、链接与代码片段，原始结构化回答和引用证据不变。

### 反馈导出的 release 元数据

- **观察事实**：本轮收集到的六份历史 JSON 都标为 `p4a`，而实际远程内测执行包和页面已标为 `p4d`。
- **工程判断**：导出器常量陈旧；反馈 schema 本身仍为 v1。
- **本轮动作**：新导出使用 `p4d`；汇总器继续接受历史 `p4a`，并在聚合结果中显示各 release 的实际计数，不改写已收集文件。

## B. 重复出现的 UX 问题

### 课件来源的可达性

- **观察事实**：去标识化主题统计中，四处开放反馈提到希望更容易点击、查看或预览课件来源。
- **解释**：当前来源行已提供文件和页码，但它主要用于定位，尚不是阅读器。
- **建议下一步**：先设计经授权的“来源定位/本地预览”边界；不得未经课程材料授权公开完整 PDF，也不得把原始课件通过公网隧道直接暴露。

### 知识图谱导航与详情位置

- **观察事实**：四处开放反馈提到图谱、详情位置、跳转或导航。
- **解释**：它与此前 P3b/P3c 的详情可发现性观察一致，但本轮不把内测收尾扩展为新的图谱重构。
- **本轮动作**：保留“图谱 → 详情”的任务导向定位，详情区提供“↑ 返回知识图谱”；两端均使用固定锚点与一次性 transient scroll event。每次明确选择均使用新的事件 identity，支持 A → B 和 A → A 的连续浏览，不恢复精确页面位置。
- **人工复测边界**：自动化测试验证锚点、事件和状态隔离；物理平滑滚动位置仍需浏览器复测。

### P4e-2：图谱返回落点与课件来源可达性

#### Observed feedback

- 内测者认可知识掌握图谱，但“返回知识图谱”后仍需继续向下滚动才能看到可选择知识点的视图控件。
- 内测者希望课件来源可以直接打开对应课程内容，而不仅是 Lec/page 定位。

#### Interpretation

- 返回按钮原先命中的是进度摘要上方的 overview 锚点；它在页面结构上有效，但不是继续选择知识点的最佳任务落点。
- citation 已包含受 Python 校验的 `source_file` 与页码范围，但原始 PDF 是 `.gitignore` 中的本地、未跟踪材料；远程运行环境不能假定具备这些文件。当前 Python 环境也没有现成 PDF 页面渲染库。

#### Decision

- 将返回动作调整为固定的 `mastery_map_graph` 图谱选择锚点；保留详情自动定位、selected concept 和一次性事件模型。
- 课件页预览本轮 `DEFER_BY_DESIGN`，不引入文件服务器、公开 PDF URL、材料复制或新依赖。

P5a 后续阶段在独立功能分支中建立受控的 runtime asset contract 后，再实现 citation 单页预览；这不改变本次 P4e 的历史结论。

#### Implementation / Deferred

- Task A 已实现并由 unit/AppTest 覆盖锚点、事件 identity、A→返回→B 与 A→返回→A。
- Task B 记录为下一阶段 source-accessibility improvement；在具备受控材料部署和页面渲染方案前，不向浏览器暴露原始文件路径。

### 诊断覆盖与题干可读性

- **观察事实**：诊断题的数量、相关性或题干可读性反复出现于开放反馈；`diagnostic_relevance` 的均值低于 QA 清晰度和诊断反馈清晰度。
- **解释**：现有 20 道 production reviewed templates 能完成当前演示闭环，但不足以证明对所有知识点的高覆盖或高精度测量。
- **建议下一步**：按课程证据与人工审核流程扩充 reviewed templates、平行题式和验收基准；不得降低 evidence gate，也不得用自动生成的开放题直接更新 mastery。

### 内测访问刷新体验

- **观察事实**：有一处开放反馈提到刷新后需再次输入访问码。
- **解释**：当前访问码只存在于浏览器 session，属于短期受控内测的刻意安全边界。
- **建议下一步**：若改善，需要单独设计短时、安全、可撤销的会话方案；不使用明文长期 cookie、URL 参数或 localStorage 保存访问码。

## C. 内容覆盖问题

- **观察事实**：六名测试者都完成课程问答、审核诊断、知识图谱、图谱到学习动作和持久化状态任务；五名完成重复练习任务。
- **解释**：这证明核心路径在本次小样本中可走通，不证明搜索算法整单元已经被充分测量。
- **建议下一步**：优先补充人工审核的验证模板及其正负例、源页证据和可用性复核，再扩大 mastery-map 中可审核覆盖。

## D. 产品范围与未来方向

- **Course Package / Course Profile**：当前课程约束是 Search Algorithms MVP 的设计目标，不是“通用性不足”的 defect。未来可将材料、知识点图、reviewed templates 和来源策略封装为可审核的课程包，而不是改成无边界聊天机器人。
- **外部题库、MCP、力扣等**：记录为后续 backlog。它们不属于当前暑期版本，也不应绕开课程材料约束或 reviewed diagnostic 边界。

## E. 当前不实施的建议

本轮不实施：完整课件公网预览、无审核自动出题、降低 evidence gate、长期保存访问码、外部题库连接、跨课程泛化、mastery 公式或 recommendation 改造。这些方向都需要独立的产品边界、课程授权或测量有效性审查。
