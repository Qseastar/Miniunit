# 内测组织者指南

## 启用与准备

仅在组内测试环境设置 `INTROAI_PILOT_MODE=1`。先确认正常应用、诊断和图谱可用；不要要求测试者提供 API Key，也不要把测试反馈目录放入仓库或共享数据库。不要分配或要求成员填写编号：页面会为每份反馈表自动生成匿名短码，该短码不是账户、身份或填写顺序。

建议每位测试者使用新的本地学习档案或明确的测试链接。测试结束时只收集其自行下载的反馈 JSON，不收集浏览器日志、数据库、完整问答或截图中的个人信息。

## 观察与支持

只解释测试流程，不提示验证题答案、不替测试者评分。尽量要求成员在讨论他人体验前独立完成，以免相互影响反馈。记录可复现的页面路径、学生可见提示和大致步骤；必要时让测试者在开放反馈中描述问题。

问题优先级：阻塞性 bug（无法继续、错误写入或隐私风险）、重大可用性问题（可继续但核心任务明显受阻）、轻微可用性问题（不影响完成）、建议（可选改进）。先处理前两类，再结合完成率和开放反馈安排下一轮。

## 反馈汇总

将下载文件放入单独的输入目录，输出放到另一个目录：

```bash
PYTHONPATH=src python tools/summarize_pilot_feedback.py feedback_downloads --output-dir pilot_summary
```

该工具离线生成 JSON、CSV 和 Markdown。它会拒绝非法文件、忽略非 JSON 文件，并按除生成时间外的相同内容去重；输入目录中按文件名最先出现的副本保留。请人工阅读开放反馈，量表统计不能替代课程审核或安全审计。
