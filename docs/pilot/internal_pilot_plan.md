# Search Algorithms 组内内测计划

## 目的与边界

本轮仅验证 Search Algorithms 黄金范式的可理解性、导航摩擦和学习记录可信度，不评测模型能力，也不改变任何掌握度规则。首轮由 6 名组员独立完成；建议每人预留约 20 分钟。内测功能默认关闭；只在受邀组内测试时以 `INTROAI_PILOT_MODE=1` 启用。

反馈由测试者自行下载 JSON 后另行发送。应用不上传反馈，不创建账号，不引入分析服务，也不把反馈写入 SQLite 学习档案。

## 固定任务

任务定义以 `data/pilot_search_algorithms_tasks.json` 为准，共六项：课程自由问答、审核诊断、知识掌握图谱、图谱到学习行动、学习状态持续追踪、重复题与复习练习。任务只说明学生可见动作和观察点；不公开模板 ID、标准答案、评分规则或内部 prompt。

## 建议流程

1. 负责人使用临时或新的本地学习档案启动测试，避免将正式演示记录混入内测。
2. 测试者按六项任务独立操作；不要求所有人具有相同的先修基础，也不把量表评分当作课程成绩。
3. 测试者填写八项 1–5 量表和可选开放反馈，生成并下载 JSON。
4. 测试者通过约定的组内渠道发送下载文件；负责人离线运行汇总命令。
5. 汇总后区分可复现 bug 与体验意见：前者记录路径、结果和影响，后者记录困惑点与建议。任何模板或评分改动仍遵循既有人工审核流程。
6. 首轮组内测试完成后，再根据稳定性与反馈决定是否开展群内志愿体验招募。

## 成功信号与停止条件

优先观察：能否理解课件来源、能否自然地进入审核诊断、知识图谱是否有助于下一步、学习记录是否值得信任、以及重复练习是否被明确标识为练习。

若发现学习记录被意外修改、反馈导出包含题目/回答/身份数据、或内测模式影响正常三标签应用，应立即停止内测并按缺陷处理，不以更多反馈掩盖问题。
